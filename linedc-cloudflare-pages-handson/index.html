この資料では、Cloudflare Pagesを使ってLINEミニアプリの開発を体験するハンズオン資料となっております。

シンプルなモバイルオーダーアプリの開発を通じて、LINEミニアプリの開発手法、そしてCloudflare Pagesを使ったアプリケーションのデプロイ、ホスティングを体験できる内容となっております。

今回作るもの

今回のシナリオは、最近よくみかけるようになったモバイルオーダーシステムをCloudflareで開発していきます。

以下の画像の通り、商品を選択し注文内容を確認したらサーバーに注文内容が送信される挙動を想定します。

システム構成

今回のシステムはすべてCloudflareで完結する構成となっています。

まず、アプリケーションはCldudflare Pagesでデプロイ、ホスティングを行います。ユーザの注文情報は、Cloudflare KVというCloudflareが提供しているサーバーレスKVS(Key Value Storage)に送信する仕組みです。

使用する技術セット

今回のシステムで使用する技術セットを以下にリストアップしていきます。

  • Next.js：今回のアプリケーションで使用するフレームワークです
  • wrangler：Cloudflareにアプリケーションをデプロイするときに使用するCLIツールです
  • Cloudflare Tunnel：ローカルのデバッグのときに使用するClouflareのトンネリングサービスです

今回のアプリケーションの全体像を紹介したところで、次のページから実際に開発を進めていきます。

今回のハンズオンの環境構築をやっていきます。

事前準備

  • LINE Developersアカウント
  • Cloudflareアカウント
  • Node.js(v20.0.0以上)

ミニアプリのチャネルを作成

まずはLINEミニアプリを作るために必要なチャネルを作成します。

以下のURLを参考にチャネルを作成します。

https://developers.line.biz/ja/docs/line-mini-app/develop/develop-overview/#create-line-mini-app-channel

ミニアプリではアイコンは任意で設定できますが、もし何か設定したい場合は以下の画像を使用しても結構です。

チャネルを作成したら、この後の手順で必要になるので開発用の本番用のLIFF URLをコピーしてどこかにメモしておきます。

wranglerの認証

すでにwranglerの認証が終わっている場合はこの手順をスキップしても問題ありません。

続いてwranglerの認証を行います。認証は以下のコマンドで行います。

npx wrangler login

コマンドを実行すると、ブラウザで以下の確認画面が表示されるはずです。もし、表示されない場合はコンソールで出力されたURLを手動で開いてください。またログイン画面が表示された場合はログインを行ってください。

確認画面で表示される内容を確認し、問題なければ「Allow」ボタンをクリックします。

以下の画面が表示されたらwranglerの認証は正常に完了しています。この画面を閉じてターミナルを確認するとコマンドが正常に実行されたことが確認できるはずです。

念の為に以下のコマンドを実行してユーザー情報を確認します。

npx wrangler whoami

以下の出力の通りユーザー情報が出力されて認証が通っていることが確認できます。

Cloudflaredのセットアップ

最後にCloudflaredのセットアップを行います。

Cloudflaredとはローカルのデバッグ時に使用するCloudflare Tunnelのクライアントツールです。

こちらはWindows、Macはそれぞれ以下のコマンドを実行すればインストール可能です。

Windows

winget install --id Cloudflare.cloudflared

Mac

brew install cloudflared

もし、Linux(WSL含む)を使って環境構築を行っている場合は以下のURLからご自身のPCに合わせたインストーラーをダウンロードし、セットアップを行ってください。

https://developers.cloudflare.com/cloudflare-one/connections/connect-networks/downloads/

以上で事前準備は完了です。次のページから実際にアプリケーションを動かしていきます。

まずは今回のアプリケーションをローカル環境で動かしてみます。

ソースコードのクローン

ソースコードは以下のコマンドを任意のディレクトリ上で実行し、クローンしておきます。

git clone https://github.com/Miura55/cloudflare-lineminiapp-handson

以下のコマンドを実行し、依存関係をインストールします。

cd cloudflare-lineminiapp-handson
npm install

設定情報を記入する

依存関係をインストールできたらアプリケーションを動かすために必要な設定情報を記入していきます。

まずは開発用の設定情報を記入します。以下のコマンドで開発用の環境情報の定義ファイルを用意します。

cat config/develop.json

任意のテキストエディタを開き、 config/develop.json に以下の内容を記述します。ここでのLIFF IDというのは、ミニアプリのチャネルを作成したときにメモしたLIFF URLの https://miniapp.line.me/ の後にある文字列のことをいいます。

{
    "LIFF_ID": "開発用のLIFFID",
    "ENABLE_VCONSOLE": "true"
}

同様に本番用の設定情報を記入します。以下のコマンドで開発用の環境情報の定義ファイルを用意します。

cat config/develop.json

任意のテキストエディタを開き、 config/production.json に以下の内容を記述します。

{
    "LIFF_ID": "本番用のLIFFID",
    "ENABLE_VCONSOLE": "false"
}

アプリケーションを起動する

設定ファイルを用意したところで、実際にアプリケーションを起動します。Next.jsではデフォルトで開発サーバーを立てるコマンドがありますが、今回はCloudflare Pagesで動かすことを想定していることと、Cloudflare KVの挙動をテストしたいのでCloudflare Pages向けにビルドを行ったあとにローカルサーバーを立ち上げます。

アプリケーションのビルドとローカルサーバーの立ち上げは以下のコマンドを実行します。

npm run preview

ビルドが終わり、以下の出力の通りになればアプリケーションは正常に立ち上がっています。

アプリケーションを立ち上げたらCloudflare Tunnelを起動します。別のターミナルを立ち上げて、以下のコマンドを実行します。

cloudflared tunnel --url localhost:8788

起動が成功したら以下の通り https://【ランダムな文字列】.trycloudflare.com が表示されます。これがローカルで起動したミニアプリのエンドポイントになるので、コピーしどこかにメモしておきます。

動作確認

それでは、動作確認をします。

LIFFのチャネルを作成したときにメモした開発用のURLを使ってブラウザで開くと以下の通りスマホから開くように誘導するQRコードが表示されるので、お手元のスマホのQRコードリーダーでミニアプリを開いてみます。

URLを開くとLINEアプリが起動し、以下の通り開発用のアプリケーションが読み込まれたら、ローカル環境のミニアプリは正常に動作しています。

画面の右下にある「vConsole」というのは、スマホでブラウザの開発者コンソールを起動するためのライブラリで、WeChatを開発しているTencentが提供しています。

このvConsoleをタップすると以下の通り開発者コンソールが起動し、アプリケーションのデバッグが効率よくなります。

このvConsoleは画面内で自由にドラッグ＆ドロップして配置することができるので、適当な場所に移動します。

すると右下にレジアイコンのボタンが表示されます。これが注文確認、送信画面を表示するためのボタンになります。

試しに適当にメニューから適当に注文したい商品を選択します。すると、注文確認のボタンにバッジが表示されて、選択した商品の数を確認できます。

いくつか商品を選択したらボタンを押して注文確認画面を開きます。注文内容が一覧で表示されるので間違って注文したものがあれば削除をし、確定したら「SUBMIT ORDER」をタップすることでkvに注文内容が記録されます。

ローカルで動作確認するときのKVのデータはアプリケーションのディレクトリ内にある .wrangler ディレクトリに保存されます。

ここまででローカル環境で動作が確認できました。

次のページではCloudflareの環境にデプロイしていきます。

KVのネームスペースを作成

ここからCloudflareにデプロイしていきます。

デプロイにあたり、今回アプリケーションで使用するKVのリソースを作成します。KVのネームスペースを作成します。

npx wrangler kv:namespace create "line-miniapp-orders"

作成されると以下の出力になり、KVのネームスペースが作成されたことが確認できます。この中にある id はアプリケーションの設定で必要になるので、どこかにメモしておきます。

 ⛅️ wrangler 3.100.0 (update available 3.101.0)
---------------------------------------------------------

🌀 Creating namespace with title "cloudflare-line-miniapp-hands-on-line-miniapp-orders"
✨ Success!
Add the following to your configuration file in your kv_namespaces array:
[[kv_namespaces]]
binding = "line_miniapp_orders"
id = "dummynamespaceid"

ネームスペースが作成されたらwrangler.tomlの kv_namespaces の項目を以下の通り修正します。

kv_namespaces = [
  { binding = "KV_ORDER", id = "ネームスペースのID" }
]

デプロイ

ここまでできたらCloudflareにデプロイしていきます。デプロイは以下のコマンドで行います。

npm run deploy

途中で以下の表示がされたら、新規でプロジェクトを作成する必要があるのでEnterキーを入力して次のステップに進みます。

? The project you specified does not exist: "cloudflare-line-miniapp-hands-on". Would you like to create it? › - Use arrow-keys. Return to submit.
❯   Create a new project

ブランチ名の指定がありますが、これもmainブランチのままEnterキーを入力します。

✔ The project you specified does not exist: "cloudflare-line-miniapp-hands-on". Would you like to create it? › Create a new project
? Enter the production branch name: › main

その後、ソースコードがデプロイされていき、以下の出力の通りURLが出力されたらデプロイは成功です。

✨ Compiled Worker successfully
✨ Uploading Worker bundle
✨ Uploading _routes.json
🌎 Deploying...
✨ Deployment complete! Take a peek over at https://217f6c5e.cloudflare-line-miniapp-hands-on.pages.dev

ここで、 https://217f6c5e.cloudflare-line-miniapp-hands-on.pages.dev の中の 217f6c5e がデプロイのハッシュ値になっており、デプロイしたタイミングで反映したアプリケーションの内容を常に表示することが可能です。

逆にハッシュ値を抜いた https://cloudflare-line-miniapp-hands-on.pages.dev が、デプロイで反映されたアプリケーションを動かすことができます。

ここで出力されるURLはユニークなので、ご自身のURLに置き換えてください。

デプロイしたばかりの時はドメインの名前解決ができてないので、URLを開いてもアクセスができません。その間に本番用のLIFFエンドポイントを設定しておきます。

開発用の時と同様にLINE Developerコンソールを開き、ミニアプリのチャネル設定画面にあるLIFFのエンドポイント設定の中の本番用にデプロイしたPagesのURLを設定します。

動作確認

それでは実際に動作確認してみましょう。

開発用のときと同様に開発用のLIFF URLからQRコードを表示させてスマホのQRコードリーダーでスキャンして以下通りデプロイしたアプリケーションが表示されればデプロイは成功です。

もし、表示されない場合は名前解決に時間がかかっている可能性があるので、時間を開けて再度開き直してみてください。

本番用では詳細なデバッグができないように右下にあったvConsoleボタンが非表示になります。

実際に商品を選択して注文すると、開発用ではローカルの環境にKVのデータが保存されていましたが、今度はCloudflare上にデータが記録されることになります。

Cloudflareのコンソール画面を開き、「ストレージとデータベース→KV」を開いて「cloudflare-line-miniapp-hands-on-line-miniapp-orders」のKVタブを確認すると注文内容が記録されていることが確認できます。

以上でCloudflare Pagesを使ったミニアプリのデプロイの開発は終了です。お疲れ様でした！

次のページでは今回構築したアプリケーションの片付けを行います。

今回構築したアプリケーションはすべてCloudflareの無料プランで動くのでそのまま残しても問題ありませんが、不要な場合はリソースを削除していただくことをおすすめします。

Pagesの削除

まずはCloudflare Pagesのリソースを削除していきます。

以下のコマンドを実行すると削除できます。

npx wrangler pages project delete cloudflare-line-miniapp-hands-on

途中で以下の質問が来た時は y を入力するとリソースが削除されます。

? Are you sure you want to delete "cloudflare-line-miniapp-hands-on"? This action cannot be undone. › (Y/n)

KVの削除

Pagesを削除するとKVのネームスペースを削除できるようになります。

以下のコマンドを実行すると削除できます。

npx wrangler kv namespace delete --binding=KV_ORDER
